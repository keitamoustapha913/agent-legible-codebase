# Benchmark environment and preflight

The runner stores Git revisions, the manifest checksum, CLI and requested model, process timeouts, sandbox mode, Python and OS versions, and a hash of selected runtime settings and global Codex context. It checks for detectable configuration drift between runs. Global features, user skills and plugins can contribute to edit-mode input and may have additional state outside that fingerprint. Discovery uses pinned navigation tools, with user config and optional integrations disabled.

- Run `--dry-run --show-commands` to inspect the execution order and exact host argv. The dry-run resolves Git revisions and reads the manifest. It starts no Codex process, check or worktree.
- After approval, the host preflight prepares both frozen revisions. Each independent success check needs its expected behavioral assertion and configured nonzero exit code on each untouched revision. Existing regression checks must pass on both sides. Use one `expected_failure` object for a single check, or an array in success-check order. Anchor the regex to a stable assertion identifier or an explicit test failure line. Keep import, fixture and infrastructure failures out of the expected-failure pattern.
- For a frozen v3 manifest, pass `--oracle-contract` with a JSON sidecar containing `manifest_sha256` and `tasks`, a mapping from task IDs to failure contracts. The harness validates the checksum before using any override.
- Edit mode's `--sandbox-smoke` explicitly approves up to one additional Codex session per task and revision. It replays the first host-green regression command in a fresh workspace-write sandbox and requires an observed matching command with a successful exit. Make that first check a small representative smoke test when designing a new manifest. A blocked smoke stops the experiment.
- Discovery uses a read-only permission profile that denies the manifest and the worktree's `.git` link. Before each trial, the local `codex sandbox` subcommand checks the manifest is unreadable and the checkout cannot be written. This local check uses no model. Unsupported configuration or failed isolation blocks discovery. The only supplied tool service lists, reads and searches tracked files. It rejects external paths and symlinks. Shell, plugins, user MCP configuration, and web search are disabled for discovery.
- A failed verifier is a separate outcome from agent completion. A missing dependency or timeout blocks preflight. Runtime test or infrastructure signals can make a trial environment-confounded even when an agent returns a final message. A workspace-write failure does not trigger a retry with broader permissions.
- On POSIX, the runner sends TERM to the process group, then KILL after a short grace period. Descendants deliberately detached into a different session are outside this guarantee. The direct child is reaped, and dead orphan children are reaped by the OS or its process supervisor. On other platforms cleanup falls back to the top-level process.

The benchmark output directory is private. It stores bounded diagnostic classifications and stream lengths and hashes. Original check output is discarded. `--keep-raw` retains sensitive Codex JSONL and Codex stderr. Host setup and verifiers execute trusted local commands outside Codex's sandbox. Review the repository and all manifest arguments before approving.

See the documented Codex [permission profile example](https://developers.openai.com/cookbook/examples/partners/harness_aware_plugin_evals/harness_aware_plugin_evals#the-codex-provider-setup) and [JSON event definitions](https://github.com/openai/codex/blob/main/codex-rs/exec/src/exec_events.rs).
